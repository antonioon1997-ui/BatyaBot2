# BatyaBot2 — установка безопасного обновления через Telegram

Текущая версия после ручной установки: **1.4**. Первое успешно установленное через Telegram минорное обновление получит номер **1.5**.

## Что добавлено

- Кнопка **«📦 Обновление бота»** в админке и команда `/update`.
- Приём ZIP только от `ADMIN_ID`.
- Обязательная проверка путей, размера, количества файлов, расширений, символических ссылок и Python-синтаксиса.
- Защита `.env`, `bot.db`, `venv`, `backups`, `logs`, `updates`, `runtime` и системных файлов.
- Предварительный список новых, изменённых, неизменённых и удаляемых файлов.
- Уведомление всех активных пользователей о начале обслуживания.
- Резервная копия кода и базы перед установкой.
- Перезапуск через systemd и проверка готовности новой версии.
- Автоматический откат, если новая версия не запускается.
- Уведомление администратора и пользователей об успехе или откате.
- Автоматическая нумерация: 1.4 → 1.5 → 1.6. Для крупного релиза в манифесте указывается `"major_update": true`, тогда, например, 1.9 → 2.0.

# 1. Подготовка

Все команды ниже рассчитаны на путь со скриншота:

```bash
/root/BatyaBot/BatyaBot2
```

Сначала проверьте фактический путь:

```bash
cd /root/BatyaBot/BatyaBot2
pwd
```

Если `pwd` показывает другой путь, замените путь во всех командах и в двух systemd-файлах из папки `deploy`.

Сохраните резервную копию текущего проекта:

```bash
cd /root/BatyaBot
cp -a BatyaBot2 "BatyaBot2_before_auto_update_$(date +%Y%m%d_%H%M%S)"
```

Особенно убедитесь, что сохранены:

```text
.env
bot.db
```

# 2. Остановка старого способа запуска

Если бот работает в `screen`:

```bash
screen -ls
screen -r ИМЯ_ИЛИ_ID_СЕССИИ
```

Внутри сессии нажмите:

```text
Ctrl+C
```

Затем:

```bash
exit
```

Если бот запущен в обычном терминале, достаточно `Ctrl+C`.

Проверьте, что старый процесс не остался:

```bash
ps aux | grep '[p]ython.*BatyaBot2/main.py'
```

Если команда ничего не вывела — бот остановлен.

# 3. Замена файлов проекта через WinSCP

В папке `/root/BatyaBot/BatyaBot2` **не удаляйте и не заменяйте**:

```text
.env
bot.db
venv/
backups/
logs/          (если есть)
deploy_backups/ (если уже есть)
```

Из нового архива загрузите поверх проекта:

```text
app/
main.py
requirements.txt
VERSION
deploy/
update_manifest.example.json
УСТАНОВКА_АВТООБНОВЛЕНИЯ.md
```

В выдаваемом архиве намеренно нет `.env` и `bot.db`, поэтому рабочие данные не будут случайно затёрты.

Убедитесь, что появились файлы:

```bash
ls -l /root/BatyaBot/BatyaBot2/app/handlers/updater.py
ls -l /root/BatyaBot/BatyaBot2/app/services/update_manager.py
ls -l /root/BatyaBot/BatyaBot2/deploy/batyabot_updater.py
cat /root/BatyaBot/BatyaBot2/VERSION
```

Последняя команда должна показать:

```text
1.4
```

# 4. Настройка `.env`

Откройте:

```bash
nano /root/BatyaBot/BatyaBot2/.env
```

Существующие `BOT_TOKEN`, `ADMIN_ID`, `DATABASE_PATH`, `TIMEZONE` и `REMINDER_TIME` сохраните. В конец добавьте:

```env
BOT_SERVICE_NAME=batyabot2.service
UPDATER_SERVICE_NAME=batyabot2-updater.service
```

Проверьте ID администратора:

```env
ADMIN_ID=123456789
```

Сохранение в nano: `Ctrl+O`, Enter, затем `Ctrl+X`.

# 5. Установка зависимостей

```bash
cd /root/BatyaBot/BatyaBot2
source venv/bin/activate
pip install -r requirements.txt
deactivate
```

---

# 6. Установка внешнего обновлятора

Обновлятор специально хранится **вне папки проекта**, чтобы не заменить самого себя во время обновления.

```bash
mkdir -p /usr/local/lib/batyabot2-updater
cp /root/BatyaBot/BatyaBot2/deploy/batyabot_updater.py /usr/local/lib/batyabot2-updater/batyabot_updater.py
chmod 700 /usr/local/lib/batyabot2-updater/batyabot_updater.py
```

Проверка:

```bash
ls -l /usr/local/lib/batyabot2-updater/batyabot_updater.py
```

---

# 7. Установка systemd-служб

Скопируйте службы:

```bash
cp /root/BatyaBot/BatyaBot2/deploy/batyabot2.service /etc/systemd/system/batyabot2.service
cp /root/BatyaBot/BatyaBot2/deploy/batyabot2-updater.service /etc/systemd/system/batyabot2-updater.service
```

Проверьте пути внутри них:

```bash
nano /etc/systemd/system/batyabot2.service
nano /etc/systemd/system/batyabot2-updater.service
```

Для вашей структуры они должны содержать:

```text
/root/BatyaBot/BatyaBot2
```

Перечитайте конфигурацию systemd:

```bash
systemctl daemon-reload
```

Включите автозапуск основного бота:

```bash
systemctl enable batyabot2.service
```

Запустите:

```bash
systemctl start batyabot2.service
```

Проверьте:

```bash
systemctl status batyabot2.service --no-pager
```

Ожидаемый статус:

```text
active (running)
```

Посмотреть последние журналы:

```bash
journalctl -u batyabot2.service -n 100 --no-pager
```

Просматривать журнал в реальном времени:

```bash
journalctl -u batyabot2.service -f
```

Выход из режима просмотра: `Ctrl+C`.

> В приложенных службах бот запускается от `root`, как и текущая установка на вашем VPS. Поэтому отдельная настройка sudo не требуется. Если позднее бот будет переведён на отдельного Linux-пользователя, потребуется ограниченное правило из `deploy/batyabot2-updater-sudoers`.

# 9. Формат будущего ZIP-обновления

Архив для загрузки через Telegram — это **не полный архив VPS**. Он должен содержать только новые или изменённые разрешённые файлы и обязательный манифест.

Пример:

```text
update_1_5.zip
├── update_manifest.json
└── app/
    └── handlers/
        └── tickets/
            └── views.py
```

Допустимы только:

```text
main.py
requirements.txt
app/**/*.py
update_manifest.json
```

Архив может содержать одну общую внешнюю папку, но лучше класть файлы сразу от корня проекта.

Пример `update_manifest.json`:

```json
{
  "major_update": false,
  "release_notes": [
    "Упрощено отображение карточки тикета",
    "Исправлен фильтр входящих задач"
  ],
  "delete": []
}
```

Для удаления старого Python-файла:

```json
{
  "major_update": false,
  "release_notes": [
    "Удалён устаревший обработчик"
  ],
  "delete": [
    "app/handlers/old_handler.py"
  ]
}
```

Для крупной версии:

```json
"major_update": true
```

Например, 1.8 станет 2.0. Пока используйте `false`.

# 10. Что архиву запрещено содержать

Обновление будет отклонено, если в архиве окажутся:

```text
.env
bot.db
venv/
.venv/
backups/
deploy_backups/
logs/
updates/
runtime/
.git/
__pycache__/
*.pyc
*.sh
*.exe
*.dll
*.so
*.bat
*.cmd
*.ps1
```

Также запрещены:

- абсолютные пути;
- `../`;
- символические ссылки;
- зашифрованные ZIP;
- более 500 файлов;
- архив больше 30 МБ;
- распакованный размер больше 80 МБ;
- Python-код с синтаксическими ошибками;
- файлы вне разрешённых путей.

При нарушении бот перечислит препятствующие файлы. Проект при этом не изменится.

# 11. Как проходит установка

После подтверждения бот:

1. Повторно проверяет архив.
2. Уведомляет всех активных пользователей о техобслуживании.
3. Создаёт задание для внешнего обновлятора.
4. Обновлятор делает копию кода и `bot.db` в `deploy_backups/`.
5. Останавливает `batyabot2.service`.
6. Заменяет только файлы из архива и выполняет разрешённые удаления из манифеста.
7. При изменении `requirements.txt` запускает `pip install -r requirements.txt`.
8. Проверяет синтаксис.
9. Увеличивает номер версии.
10. Запускает бота.
11. Ждёт до 60 секунд подтверждения готовности.
12. При успехе сообщает администратору и всем активным участникам об изменениях.
13. При ошибке возвращает предыдущий код и базу, запускает прежнюю версию и уведомляет об откате.

Хранятся последние 10 резервных копий обновлений:

```bash
ls -lah /root/BatyaBot/BatyaBot2/deploy_backups
```

# 13. Важное правило для первого теста

Первое тестовое обновление должно быть маленьким и обратимым: один текст или одна безопасная функция без изменения базы. После установки проверьте:

```text
/health
```

и журналы обеих служб. Только после успешного теста используйте Telegram-обновления для крупных изменений.
